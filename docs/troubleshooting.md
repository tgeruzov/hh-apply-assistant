# Решение проблем

## Панель не появилась

Проверьте по порядку:

1. Tampermonkey и HH Apply Assistant включены.
2. В Chrome 138+ для Tampermonkey включён **Allow User Scripts**; в старом Chromium включён Developer mode.
3. Site access разрешает работу на hh.ru.
4. URL соответствует одному из `@match`: поиск, страница вакансии или `/applicant/vacancy_response`.
5. После установки или изменения кода страница была обновлена.

На узком окне панель может быть закрыта: найдите вертикальный переключатель HH Apply Assistant. Если расширение установлено вручную, убедитесь, что в редактор попал весь файл вместе с metadata block.

## Install URL показывает текст

Обычно Tampermonkey не получил доступ к User Scripts API или выключен. Выполните шаги из [installation.md](installation.md#1-установите-tampermonkey). После изменения разрешения перезагрузите контекст расширения или браузер и снова откройте `.user.js` URL.

## Прогон не начинается

Статус **Занято другой вкладкой** означает активный cross-tab lease. Остановите запуск в другой вкладке штатной кнопкой. Если вкладка аварийно закрылась, stale lease перестаёт считаться активным через 30 секунд; после этого повторите Start.

Если статус указывает ошибку сохранения, проверьте доступность browser storage и свободное место. Критические записи работают fail-closed: продолжение без подтверждённого состояния намеренно блокируется.

## Ничего не найдено на выдаче

Скрипт обрабатывает только текущую страницу и по умолчанию пропускает скрытые кнопки. Уже записанные в `processed_ids` вакансии не выбираются повторно даже после Stop/Start.

Если нужно повторить обработку, используйте **Сбросить историю**. Это также обнулит счётчик и статистику текущей вкладки, но не изменит лимит.

Если выдача содержит новые видимые карточки, а Healthcheck сообщает ошибку обязательного selector, hh.ru мог изменить DOM. Скачайте diagnostic report после воспроизведения и оформите bug report.

## Вакансия оказалась в ручной очереди

Это ожидаемый исход для questionnaire fields, выключенного reject-warning, отсутствующей кнопки отправки, таймаута и неподтверждённого результата. Откройте запись и завершите сценарий вручную. Очередь не означает, что отклик точно не был отправлен; она означает, что automation не смог безопасно подтвердить результат.

## CAPTCHA

Скрипт распознаёт явные captcha widgets, характерный path или короткое видимое антибот-сообщение в dialog/overlay. После обнаружения он снимает running state и lease, затем останавливается.

Решите проверку вручную, вернитесь на поддерживаемую страницу и запустите новый run. Скрипт не обходит CAPTCHA и не возобновляется автоматически после её решения.

## После навигации состояние выглядит неверно

1. Нажмите **Остановить**.
2. Проверьте другие вкладки hh.ru.
3. Обновите поддерживаемую страницу.
4. Запустите снова.

Не удаляйте все site data hh.ru как первый шаг: это может завершить авторизацию. Для точечного сброса используйте ключи из [storage.md](storage.md#очистка).

## Обновление не найдено

- проверьте, что установленный script содержит `@updateURL`, `@downloadURL` и `@version`;
- разрешите Tampermonkey доступ к `raw.githubusercontent.com` либо временно выберите Site access **On all sites**;
- вручную откройте [install URL](https://raw.githubusercontent.com/tgeruzov/hh-auto-responder/main/hh-apply-assistant.user.js) и сравните предложенную версию;
- убедитесь, что локальная development-копия не заменила release script с другим именем/namespace.

## Подготовка bug report

1. Перейдите на страницу, где воспроизводится проблема.
2. Откройте **Диагностика** и выполните Healthcheck.
3. Воспроизведите ошибку.
4. Скачайте report.
5. Удалите чувствительные URL/query parameters, персональные фрагменты разметки, cookies и токены, если они были добавлены вручную в описание.
6. Укажите версию HH Apply Assistant, Chrome, Tampermonkey, режим, тип страницы, шаги, ожидаемый и фактический результат.

Используйте [bug report form](https://github.com/tgeruzov/hh-auto-responder/issues/new/choose). Состав отчёта подробно описан в [diagnostics.md](diagnostics.md).
