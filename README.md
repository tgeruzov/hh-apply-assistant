HH Apply Assistant — userscript для автоматизации стандартных откликов на вакансии hh.ru. Он добавляет на страницы поиска и вакансий боковую панель, обрабатывает карточки текущей выдачи и сохраняет сценарии с вопросами или неподтверждённым результатом в ручную очередь.

[Установить HH Apply Assistant](https://raw.githubusercontent.com/tgeruzov/hh-auto-responder/main/hh-apply-assistant.user.js) · [Инструкция](docs/installation.md) · [Руководство](docs/usage.md) · [Решение проблем](docs/troubleshooting.md)

> [!WARNING]
> Это независимый проект, не связанный с hh.ru или HeadHunter. Правила и ограничения платформы могут меняться; автоматизация может привести к CAPTCHA, временным ограничениям или блокировке. Ответственность за способ и последствия использования остаётся у пользователя.

## Возможности

- обработка ещё не пройденных вакансий на текущей странице поиска;
- стандартные формы отклика, сопроводительное письмо и проверка подтверждения отправки;
- четыре профиля темпа: **Безопасный**, **Баланс**, **Быстрый** и **Турбо**;
- лимит успешных откликов за запуск, управление Start/Stop и статистика;
- ручная очередь для анкет, предупреждений об отказе и неясных исходов;
- локальная диагностика: журнал, поиск и фильтры, метрики, Healthcheck и экспорт отчёта;
- русский и английский интерфейс;
- восстановление после переходов между страницами и блокировка параллельного запуска в другой вкладке;
- остановка при CAPTCHA и критических ошибках сохранения состояния.

Скрипт зависит от DOM и сценариев hh.ru. Изменение разметки сайта может потребовать обновления селекторов или логики распознавания.

## Интерфейс

На широком экране панель закрепляется справа от страницы hh.ru; при меньшей ширине она становится компактнее, затем переходит в overlay. Панель можно свернуть, не останавливая активный прогон.

Актуальных скриншотов пока нет. Для них подготовлен каталог [docs/assets/screenshots](docs/assets/screenshots/README.md); изображения будут добавлены после отдельной проверки интерфейса без персональных данных.

## Установка

Основной проверяемый сценарий: настольный Chrome и актуальный Tampermonkey.

1. Установите [Tampermonkey](https://www.tampermonkey.net/).
2. В Chrome 138 и новее откройте карточку расширения Tampermonkey и включите **Allow User Scripts / Разрешить пользовательские скрипты**. В более старых Chromium-браузерах для User Scripts API используется **Developer mode / Режим разработчика**.
3. Для работы на hh.ru и автоматической проверки обновлений оставьте Tampermonkey доступ к сайтам. Подробности и вариант с ограниченным Site access описаны в [инструкции](docs/installation.md).
4. Откройте [install URL](https://raw.githubusercontent.com/tgeruzov/hh-auto-responder/main/hh-apply-assistant.user.js) и подтвердите установку в Tampermonkey.
5. Войдите в hh.ru, откройте [поиск вакансий](https://hh.ru/search/vacancy) и обновите страницу. Справа должна появиться панель HH Apply Assistant.

Metadata содержит `@updateURL` и `@downloadURL`. После публикации новой версии в `main` Tampermonkey сможет получить её обычным механизмом обновления userscripts. Ручная установка из редактора остаётся запасным вариантом.

## Быстрый старт

1. Настройте выдачу hh.ru и откройте нужную страницу результатов.
2. В панели выберите режим. По умолчанию используется **Баланс**, лимит равен 50, сопроводительное письмо включено.
3. Проверьте текст письма. Настройка отклика при предупреждении HH по умолчанию выключена.
4. Нажмите **Запустить отклики**. Лимит считает только подтверждённые успешные отправки текущего запуска.
5. Следите за статусом и разделами **Ручная очередь** и **Диагностика**. Для остановки нажмите **Остановить**.

История обработанных вакансий хранится в пределах вкладки и не сбрасывается при новом Start. Скрипт не переходит на следующую страницу выдачи автоматически.

## Ограничения и данные

- Анкеты с вопросами работодателя не заполняются автоматически.
- CAPTCHA не обходится: прогон останавливается до ручного решения и нового запуска.
- Неполученное или неоднозначное подтверждение не считается успешным откликом.
- Настройки, письмо, ручная очередь и diagnostics хранятся в `localStorage` origin `hh.ru`; состояние запуска и история вкладки — в `sessionStorage`.
- Runtime не содержит `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `@require` или `@resource`. Экспорты создаются локально через `Blob`.
- Diagnostic export включает URL/пути, user agent, состояние запуска, метрики, журнал и ограниченные фрагменты диагностической разметки. Перед публикацией его нужно просмотреть и отредактировать.

Подробности: [хранение](docs/storage.md), [диагностика](docs/diagnostics.md) и [privacy](PRIVACY.md).
